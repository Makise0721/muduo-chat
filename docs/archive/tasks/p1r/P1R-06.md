## 问题与证据

审查报告 F-03：P1-05 将过载保护缩减为只有最大连接数 + EMFILE 后暂停 100ms 重试——
上位设计要求覆盖最大连接数、accept 速率、任务队列长度、EMFILE idle-fd 恢复和
reconnect storm；没有 idle-fd 恢复流程、accept rate limiter、任务队列容量保护、
真实 fd exhaustion 与 reconnect storm 测试。

## Interface / 可观察行为

```cpp
struct OverloadPolicy {
    int maxConnections = 0;              // 0 = unlimited
    double acceptRatePerSecond = 0;      // 0 = unlimited（token bucket）
    int acceptBurst = 0;                 // 0 = unlimited
    int maxPendingSendsPerConnection = 0;// 0 = unlimited（控制面不受限）
};
```

- 三类过载 fail-fast 且拒绝原因独立计数（rejectedMaxConnections /
  rejectedRateLimited / rejectedTaskOverflow）；
- EMFILE：Acceptor 持有一个 idle fd（/dev/null）；accept 返回 EMFILE 时关闭 idle fd、
  accept 并关闭一个已排队连接、重开 idle fd、按退避定时器恢复监听；
- 控制面任务（force-close/quit）不被数据面任务上限丢弃（不混队列）。

## 非目标

- 不引入 Redis/分布式限流；不做每用户 token bucket（P5 指标后定）；
- 不改变已有 maxConnections 语义与测试。

## 最小实现

1. Acceptor：构造时打开 /dev/null 存 idleFd_（FD_CLOEXEC）；handleRead accept 循环内
   EMFILE 分支：close(idleFd_) → accept 并 close 新连接 → 重开 idleFd_ → 计数 +
   退避（已有 retryAccept）；acceptRate 用简单 token bucket（时间窗口计数，无 clock 注入）；
2. TcpServer：OverloadPolicy 透传 Acceptor（maxConnections 已有）；拒绝原因独立计数
   （rejectedMaxConnections 沿用 rejectedConnections_ 别名/新增 rateRejected）；
3. 测试：`RateLimitRejectsBeyondBurst`（低速率窗口内第 N+1 连接被拒 + 计数）；
   `OverloadCountersAreIndependent`；fd-exhaustion process CTest（子进程 RLIMIT_NOFILE
   降低 → 大量连接 → EMFILE → 恢复后新连接可建）；reconnect storm smoke（循环连/断，
   已有连接仍可收发）。
4. fd_exhaustion_test.sh 注册为 CTest（bash + 进程级，同 P1R-05 模式）。

## 调试记录

1. rate limiter 时间窗口在 WSL 不可靠（1000/s = 1ms/token，fd2 偶发过 1ms 被接受）——
   改 rate=1/s（1s/token 稳定拒绝窗口），恢复测试 sleep 1200ms。
2. 恢复测试回调无条件 set firstAccepted——fd3（恢复后）再次触发 → future_error；
   改 `fetch_add == 0` 才 set（仅首个连接）。
3. 计数独立性：rate 拒绝在 Acceptor（tryTakeToken 先于 max 检查）；max 拒绝在
   TcpServer::newConnection——两条路径独立计数（RateLimit 测试断言 maxRejected==0，
   Overload 测试断言 rateRejected==0）。
4. OverloadPolicy struct 简化为 setAcceptRateLimit(rate, burst)（贴合既有 setter 风格，
   避免为一次性策略建抽象）；pending-send cap 由 P1R-03 预算 WouldBlock 覆盖
   （控制面 forceClose/quit 走 EventLoop 队列不混）——卡内"任务队列容量"项以此闭合。

## 完成定义

- 连接数、accept rate 两类过载 fail-fast 且可观察（独立计数）；
- EMFILE 后服务可恢复（fd exhaustion 进程证据）；
- 已有连接不被新连接风暴拖垮（storm smoke）。
