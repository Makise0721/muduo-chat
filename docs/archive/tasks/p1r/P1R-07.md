## 问题与证据

审查报告 A-01：`cancel(TimerId{})` 在 `id.timer->expiration()` 处空指针崩溃（默认构造
TimerId 无 timer）；F-05：重复 timer 迟到时按 `now + interval` 重置——延迟累积成长期
漂移（长回调或系统停滞使相位永久丢失）。

## Interface / 可观察行为

- 默认、已取消、已触发的 TimerId 取消均为幂等 no-op；
- 重复 timer 以 planned deadline 推进；调度策略：跳过已错过周期、不并发补跑，
  下一 deadline 是首个严格晚于当前时刻的 planned phase。

## RED

`TimerQueueTest.CancelDefaultTimerIdIsNoOp`：修复前 `cancel(TimerId{})` 段错误
（`id.timer->expiration()` 空解引用）；`LongCallbackKeepsPlannedPhase`：修复前
restart 按 now+interval 重置，长回调（120ms > 50ms interval）相位逐周期漂移。

## 最小实现

1. `cancel`：`!id.timer` 提前返回（幂等 no-op）；
2. `Timer::restart`：`expiration_ += interval` 保持 planned phase；仍 <= now 时
   按间隔跳过整周期（delta/interval + 1）到首个严格晚于 now 的相位点。
