## 问题与证据

审查报告 A-03：多数测试目标直接重新编译生产 `.cc`（tests/CMakeLists.txt:3-166），
同一生产源被 `mymuduo` 库 target 与多个 test target 各编译一次；test target 为
C++14（gtest 1.14 要求），生产库为 C++11——"测试通过的对象代码 ≠ 最终链接进
ChatServer 的对象代码"。受影响目标：BufferTest、EventLoopTest、
EventLoopThreadPoolTest、TcpConnectionTest、StreamCodecTest、
LegacyJsonLineCodecTest、BinaryFrameCodecTest、TimerQueueTest、
BackpressureTest、TcpServerTest、LoggerTest（11 个）。

## Interface / 可观察行为

- 网络库对象代码只由 `mymuduo` target 编译一次；
- 相关单元测试链接 `mymuduo` target（共享库），与生产一致的语言标准/宏/sanitizer flags；
- `compile_commands.json` 中每个 `mymuduo/*.cc` 恰有一条编译条目（CTest 可检）；
- 测试数量与行为不回退（78 项）。

## 非目标

- 不为测试暴露生产私有成员；不改测试源码；
- 不改变生产构建方式与链接（ChatServer 已链接 mymuduo）；
- 不处理 chat-bench（tools 独立）。

## RED

命令：

```powershell
wsl.exe -d Ubuntu -- bash -c "cmake --fresh -S . -B ~/muduo-chat-build/p1r01 -DCMAKE_BUILD_TYPE=Debug -DENABLE_TESTS=ON -DCMAKE_EXPORT_COMPILE_COMMANDS=ON > /dev/null 2>&1; python3 /mnt/d/agent_learning/muduo-chat/tests/scripts/check_single_compile.py ~/muduo-chat-build/p1r01/compile_commands.json; echo EXIT=$?"
```

预期失败：每个重复编译的生产 .cc 报一行（如 `mymuduo/Buffer.cc compiled by BufferTest`）。
实际证据：配置后 `check_single_compile.py` 列出 11 个 test target 重复编译的条目（如
Buffer.cc 出现 2 次：mymuduo + BufferTest）。

## 最小实现

1. 顶层 CMakeLists.txt：`set(CMAKE_EXPORT_COMPILE_COMMANDS ON)`；
2. tests/CMakeLists.txt：11 个目标源列表只保留 unit 测试源码，链接
   `mymuduo Threads::Threads`；BenchStatsTest 不动（无生产 .cc）；
3. 新增 `tests/scripts/check_single_compile.py`：解析 compile_commands.json，凡
   `mymuduo/*.cc` 出现多条编译条目即 exit 1 并列出目标名；注册为 CTest
   `single-compile-check`；
4. 不改变测试的 include 目录（仍需要 mymuduo 头）。

## 调试记录

1. `find_package(PythonInterp)` 在 CMake 3.28 触发 CMP0148 dev warning（模块已移除）——
   改用 `find_program(python3 REQUIRED)`（跨版本可用，无 policy 依赖）。

   79/79 运行即证明 rpath 有效；ChatServer 既有链接方式不受影响。
