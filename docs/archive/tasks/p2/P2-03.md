## 接口/行为

- `BlockingExecutor(EventLoop*, workerCount, queueCapacity)`：
  `submit(task, completion, deadlineMs) -> SubmitResult{Accepted, RejectedFull, RejectedShutdown}`；
  慢任务在 worker 线程执行，completion 经 `loop->runInLoop` 保证回到 EventLoop 线程；
  队列容量有界，满则 fail-fast（不阻塞）；deadlineMs>0 的任务过期（自提交起）
  被跳过且不回调；shutdown 幂等、拒绝新提交、有界 drain 在途任务（队列有界）。
- `InlineBlockingExecutor`：同签名同步 adapter（测试/开发用，无线程）。
- 完成定义门槛预记录：EventLoop 探针 50ms 间隔，慢 DB 任务（100ms × 10、2 worker）
  下 probe 最大间隔必须 < 200ms。

## 过程（RED → GREEN）

- RED-1：`AcceptsUntilQueueIsFullThenFailsFast` 首版时序假设错误（提交后 worker
  取走慢任务前存在窗口，µs 内连发 3 提交全部入队）→ 失败（第二个提交被拒）。
- GREEN：以"慢任务已开始"promise 使时序确定性 → 7/7 通过。
- 修复中顺带确认：executor 析构先于 EventLoop 析构（成员声明顺序），shutdown
  join 无 TSan 报告。
