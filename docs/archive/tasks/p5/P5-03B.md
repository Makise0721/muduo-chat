## 问题与证据（实测归因）

P5-03 只修实测热点（计划 §9.5）。本卡选定 **序列化拷贝消除（ProtocolCodec JSON）**——计划候选台账**候选三**（序列化拷贝消除 ProtocolCodec JSON），开卡理由（实测归因证据）：

- **归因链条（gprof 实证，纯 CPU）**：P5-02 gprof flat profile（`/mnt/d/muduo-chat-build/p5-02-gprof-profile.txt`，reliable-direct 负载）明确登记 nlohmann JSON lexer/serializer 与 Buffer 字节操作为热点：
  - `nlohmann::json` **lexer `get()` 295,520 次调用**、`add()` 198,474、`serializer::decode()` 188,648、`set_parents()` 144,378、`~basic_json` 156,147、`assert_invariant` 541,371、`_Rb_tree`（std::map 对象）插入/查找 ~172k-226k——**JSON 解析与序列化（协议编解码路径）**（p5-baseline.md「热点 Top」第 2 条显式标注）。
  - `std::vector<char>` **emplace_back 317,263、size 107,552、empty 12,450**、`std::__new_allocator<char>::~__new_allocator` 245,858——**Buffer 字节操作与序列化往返拷贝**（p5-baseline.md 热点 Top 第 1 条）。
  - 结论：`ProtocolCodec` 服务器回复路径**先构造完整 `nlohmann::json` 对象（RB-tree 分配/插入）再 `.dump()` 序列化成 `std::string` → Buffer**，产生大量堆分配、lexer/serializer 调用与字节往返拷贝。这是**纯 CPU 热路径**，与 P5-03A 的 DB 串行写（DB I/O 对 gprof 不可见）不同——gprof 已实证可采样（0.13s 累计 16 采样中 lexer/vector 占主要）。
- **与其余候选对比（选本项理由）**：
  - **Outbox lease 批量 claim**：属 DB 写路径（与候选一同类，受 DB I/O 串行主瓶颈制约，gprof 归因弱）；且候选一刚证明 DB 写路径攒批在 HOL 同步语义下接线复杂度过高。
  - **Buffer 分配复用**：归因与序列化路径重叠（vector<char> 字节操作），但需动 Buffer/编码基础设施，改动面大于本项、单变量性弱于直接改序列化。
  - **锁竞争缓解（accept 事务 FOR UPDATE / registry 锁分片）**：FOR UPDATE 串行属 DB 层，gprof 不可见；registry 锁分片为并发结构改动、正确性风险高于本项。
  - 本项：**gprof 实证最直接**（lexer 295k + Buffer 字节操作）、**纯 CPU 优化**（不碰 DB/HOL/并发结构）、**单变量**（只改服务器回复编码）、**协议语义零变化**（wire 字节与 `dump()` 完全一致，golden 锚定）、**正确性风险低**（字节等价契约 + 既有 golden）。
- 结论：选候选三。若实测复测后门槛未达，循环协议第 6 步 revert 并将结论入台账，另选候选——不预设结果。

## 最小实现（单变量）

只改服务器回复编码路径，其它不动：

- 落点（开卡圈定，最终以最小实现为准）：`ProtocolCodec` 的 `buildMessageAcceptedReply` / `buildErrorReply` 序列化路径（ProtocolCodec.cpp:404-429 与其调用侧 `.dump()` → Buffer）。最小实现 = 引入零拷贝/直接字符串 encode seam（如返回 `std::string` 的直接序列化函数，或编码辅助把固定字段直接写入字符串，避免构造完整 `nlohmann::json` 对象 + dump），产出与既有 `json.dump()` **逐字节一致**的 wire 字节。
- 单变量纪律：不引入配置项、不改 accept 事务、不改协议字段/errmsg、不改解析路径（`parseChatMessage`、DELIVERY_ACK）、不改 `ReliableMessageMetrics`、不改 Buffer 基础设施本身。只动服务器回复**序列化**。
- 若新增 encode seam 需触碰 `ProtocolCodec.hpp` 接口，沿用既有自由函数形态（保持 mymuduo 无关 TU），既有测试替身零伴改。
- 字节等价以 `ReliableProtocolGolden` 既有 golden 锚定：新实现必须与 golden fixture 逐字节一致，否则不达标。
