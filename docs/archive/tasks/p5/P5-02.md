## 环境授权与 spike 结论（开卡登记，2026-08-24，luna_worker）

授权清单项（计划 §9.0 环境授权清单）：**linux-tools（perf）**、valgrind、FlameGraph 脚本仓库。逐项 spike 结论：

### linux-tools（perf）安装尝试结果

- 环境事实：WSL2 内核 `6.6.87.2-microsoft-standard-WSL2`；`apt-cache policy linux-tools-common` → Candidate `6.8.0-138.138`，未安装。
- 尝试命令：`sudo -n apt-get install -y linux-tools-common linux-tools-generic`。
- 结果：**`sudo: a password is required`**（无 passwordless sudo）。本环境 sudo 需密码交互 → 依任务协议「有密码交互则停」，登记为 **需用户授权交互**（perf 安装无法在本 worker 内无授权完成；不做交互密码输入）。
- 判定：perf 不可用（无法安装、无法跑 `perf stat/record`）。WSL2 虚拟化下即便装上也大概率 `permission denied / no PMU`（已登记为预期），故不阻塞 fallback。

### valgrind / FlameGraph

- valgrind：未安装（which 无命中）；未尝试安装（同样受 sudo 密码交互限制；且本项目 Debug/ASan/TSan 已覆盖内存与数据竞争检测，valgrind 在 profile 面非必需——按需）。
- FlameGraph：脚本仓库（GitHub brendangregg）未安装；依赖 perf 输出，perf 不可用则本环境不可用（登记）。

### WSL2 perf 不可用 → fallback 组合选择（冻结，D-fallback）

profile 工具链 fallback 组合，按序选择，选择理由逐一登记：

1. **`-pg` gprof 构建变体（首选）**——理由：`gprof` 已装（GNU gprof 2.42）、`gcc -pg` 编译通过（实测 `pg_compile_ok`）、`gmon.out` 正常生成且 gprof 可解析（实测 exit 0，样本可定位 `foo` 函数）。零额外授权。**限制**：gprof 基于 `-pg` 插桩采样（PC 采样近似 + 无时钟级准确、无 cache miss/syscall 计数）；**触及构建系统 → 需单独提交并登记**。
2. **`strace -cf` syscall 计数**——未安装；如需需授权安装（登记为按需，不默认）。若可用可量化 syscall 占比（P5-04 sendmmsg 候选前置）。
3. **定点手工计时 instrumentation**——不触构建系统的定点计时（如模块内已有指标：DB lock wait、executor queue depth/drop、oldest pending、outbox lag，取自 P5-00 `/metrics` 与 SIGUSR1 快照），零工具依赖，恒可用，作为 profile 的补充量化面。
4. **callgrind（valgrind 组件）**——未安装；依赖 valgrind 授权安装（按需，登记）。可用时给出精确指令计数/调用图，但慢（数量级放慢），不适于吞吐基线，仅作定点热点确认。

**选定组合**：`-pg` gprof 构建变体（首选）+ 定点手工计时 instrumentation（P5-00 指标面，恒可用）+ 逐场景 `RSS`（`/proc/<pid>/status VmRSS`，无工具依赖）。FlameGraph/perf/cache miss 仅在 perf 可用时才报告（本环境登记为不可用）。

### 插桩变体提交登记

`-pg` gprof 构建变体若通过新增 CMake 选项（如 `-DENABLE_GPROF`）或修改 `tools/CMakeLists.txt`/`tests/CMakeLists.txt` 触达构建系统，**必须与主线 `perf(bench): freeze methodology and capture p5 baseline` 分开、单独提交并登记于本卡**（沿 §9.4「触及构建系统的插桩变体单独提交」）。若实现为仅命令行加 `-pg` 的独立构建树（不改任何仓库文件、只加编译 flag），则不属于仓库改动、不需单独提交——优先此路径。

## 设计决定（开卡定案，RED 前冻结）

- **D1 方法学冻结（写入 `docs/specs/benchmark-methodology.md`）**：
  - 硬件：Intel Core i9-14900HX（32 线程，实测 P2 报告），记录 CPU 型号/核数。
  - kernel：`6.6.87.2-microsoft-standard-WSL2`（WSL2 单机）。
  - 编译 flags：Debug（`-g -std=c++11`）+ 记录 CXX_FLAGS_STRING；正式基线构建树固定（独立 binary tree，非源码树）。
  - 数据规模（预建用户数与 Conversation 分布）：基准数据集预建 N 用户 + Conversation 分布（direct 为主、少量 group、hot Conversation 单一离线目标——用于验证 P3-11 登记的行锁串行瓶颈）；规模常数开卡时冻结（卡内登记：预建用户数、Conversation 数、hot 目标固定 ID，见「数据规模冻结值」节）。
  - 网络模型：回环（127.0.0.1），本地单机。
  - warmup 时长与次数：每场景正式测量前 warmup 固定轮数/时长（见「验证参数冻结值」节），丢弃 warmup 采样。
  - 正式重复：每场景 ≥5 次（同 commit 隔日两轮验证即 ≥5 样本）。
  - 统计口径：均值 + 95% CI（正态近似 t 分布，CI = mean ± t_{0.975,n-1}·(s/√n)）。
  - 结果 schema 版本：**bench-result-v1**（字段集冻结于 `docs/specs/benchmark-methodology.md` 与 runner 输出，见 D3）。
- **D2 场景矩阵（固定，每场景记录字段清单见 D3）**：connect、echo、slow-consumer（chat-bench 三件套）＋ reliable direct、reliable group、hot Conversation（单一离线目标，验证行锁串行）、DB backpressure（慢查询注入）、Redis down、Kafka pause。共 9 场景。每场景记录：msg/s、端到端 p50/p95/p99、DB lock wait、executor queue depth/drop、oldest pending、outbox lag、RSS（来自 P5-00 `/metrics`/SIGUSR1 快照 + `/proc`）。
- **D3 runner 形态与结果 schema（`bench-result-v1`）**：
  - runner：`tools/bench/run.py`（或 `tests/scripts/p5_02_runner.py`）——编排 ChatServer 起停、依赖存活核对（MySQL/Redis/Kafka）、topic 卫生（fresh topic / consumer group offset=latest，避免 P4-07 积压重放 churn 污染）、逐场景 warmup + 正式 ≥5 次、调用 chat-bench / chat_load / 慢查询注入 / 故障注入、采集 `/metrics` 与 `/proc` RSS、输出原始 JSON 序列。
  - 负载脚本：`tools/chat_load.py`（既有，reliable direct/group/hot 场景）＋ `chat-bench`（connect/echo/slow-consumer）＋ 新增故障注入封装（DB backpressure / Redis down / Kafka pause 沿 P4-06 chaos 场景族）。
  - 统计脚本：`tests/scripts/p5_02_stats.py`——读原始 JSON 序列，输出均值 + 95% CI 与**逐场景变异系数（CV=σ/μ）**（作为 P5-03 优化门槛的分母依据，§9.4 验证命令）。
  - 结果 schema `bench-result-v1`：固定 JSON 字段（schema_version、commit、timestamp、host{kernel,cpu,ulimit}、build{commit,cxx_flags,build_type}、scenario、workload 参数、warmup 元数据、repetitions≥5、每重复 per-scenario 指标对象、统计{mean,ci95_low,ci95_high,cv}）。
- **D4 统计脚本与 CI 口径**：均值 + 95% CI（t 分布，见 D1）；变异系数 CV 逐场景入档，作为噪声上界（P5-03 门槛分母）。CI 区间 = 完成定义「CI 区间」交付物。
- **D5 profile 产物对齐 commit**：profile 产物（`-pg` gprof 输出、gmon.out、手工计时/RSS 采集）与本次基线的 commit 对齐记录——报告标注 commit、构建树、原始产物路径（五元组定位：commit/机器/配置/原始输出/统计脚本，§9.7）。热点 Top 列表带 profile 产物链接。
- **D-fallback（环境授权）**：见「环境授权与 spike 结论」节（gprof 首选 + 定点计时 + RSS；perf/FlameGraph/cache miss 本环境不可用）。
