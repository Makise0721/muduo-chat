## 问题与证据

EVOLUTION_PLAN §2.1 在案：#4 Logger 全局共享可变状态（宏每次 setLogLevel 写 logLevel_ +
同步写 std::cout + Timestamp::toString 共享）——TSan 全量失败 3 项的 2 项归因于此；
同步输出进热路径（每事件 LOG_INFO）。

## Interface / 可观察行为（EVOLUTION_PLAN §9 P1-06）

- LOG_* 宏调用点不变；一次调用携带级别；
- 有界异步队列（默认 4096）+ 独立 logging 线程；热路径不做磁盘 I/O；
- 队列满：丢弃新日志，`droppedCount()` 可观察；
- `Logger::setLogLevel` 级别过滤（低于级别零开销跳过）；
- `Logger::flush()`：阻塞至队列排空（测试/退出用）；LOG_FATAL 强制 flush 后 exit；
- 日志线程单线程写输出 → 消除 setLogLevel/cout 竞态（TSan 在案）。

## 最小实现

- Logger：atomic logLevel_ + mutex/condvar + 有界 deque + logging 线程 + dropped 计数 +
  flush()/droppedCount()/注入输出流（测试 seam）；
- LOG_* 宏：级别检查（跳过）→ 栈 buffer snprintf → log(level, buf) 入队；
- LOG_FATAL：入队 + flushAll + exit(-1)；
- 析构：join logging 线程（退出前排空）。
