## 问题与证据

TSan 全量剩余失败（68/69/15 等，P0-03A 记录在案）：
跨线程 `queueInLoop`/`quit` 的 `wakeup()` write(eventfd) 与 `~EventLoop` 的
close(eventfd) 无同步边——close 后 fd 号可被复用，后续 write 可能写到错误对象
（真实 UAF 风险，非仅 TSan 洁癖）。TimerQueue 同款（跨线程 addTimer 的
timerfd_settime vs ~TimerQueue close）。

## Interface / 可观察行为

- wakeupFd_/timerfd_ 生命周期由互斥锁保护：write/settime 与 close 互斥；
- close 后 fd 置 -1，后续调用安全跳过；
- 热路径代价：wakeup 一次锁（P5 评估性能）。

## 非目标

- 不改变 API/行为语义；不做无锁优化。

## 最小实现

- EventLoop：`std::mutex wakeupMutex_`；wakeup() 锁内写（fd>=0 检查）；
  ~EventLoop 锁内 close + 置 -1；
- TimerQueue：timerfd_ 非 const；~TimerQueue 锁内 close + 置 -1；
  resetTimerfd 检查 fd>=0。
