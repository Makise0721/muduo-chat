## 问题与证据

当前 sendInLoop：缓冲无界增长；High Water Mark 只通知不暂停读、无硬上限、无超时。
EVOLUTION_PLAN §4.4 要求完整状态机。

## Interface / 可观察行为（EVOLUTION_PLAN §4.4）

```cpp
struct WriteBufferLimits {
    size_t pauseReadBytes;
    size_t resumeReadBytes;
    size_t hardLimitBytes;
    std::chrono::milliseconds stallTimeout;
};
```

- 状态机：Normal --达到 pauseRead--> Backpressured --降至 resumeRead--> Normal；
  Backpressured --达到 hardLimit 或 stallTimeout 到期--> 断开；
- `send` 返回 `SendResult { Accepted, Backpressured, Closed, TooLarge }`；
- 约束 `resumeReadBytes < pauseReadBytes < hardLimitBytes`（非法配置拒绝）；
- 阈值由 TcpServer 一次配置，业务 handler 不操作；
- 现有 void send 调用方源码兼容（返回值可丢弃）；
- 旧 highWaterMarkCallback 保留（默认阈值 64MiB）。

## 调试记录

1. 跨线程 send 返回值竞态：测试先 sleep 后读非原子结果——改 promise 同步。
2. SIGPIPE：对端关闭后写入——gtest_discover_tests 每测试独立进程，SIG_IGN 需逐测试设置；
   同时记录**生产观察**：ChatServer main 未忽略 SIGPIPE（对端 RST 后可杀进程），
   P1-05 过载/退出任务处理。
3. writeComplete 语义误用：单条消息全写也会触发（非"缓冲排空"信号）——恢复断言改
   事件驱动递归 send 重试（queueInLoop）。
4. **循环引用泄漏（LSan 264KB→526KB）**：stall timer 回调捕获 shared_from_this()，
   Timer 又被 stallTimerId_ 成员持有 → conn→Timer→callback→conn 环，连接永不析构。
   修复：cancelStallTimer/forceClose/handleClose/connectDestroyed 清理 stallTimerId_
   （Timer 析构 → callback 释放 self → 环破）。ASan+LSan 68/68 验证。
5. 调试中发现 WSL /mnt/d mtime 秒级精度导致 make 误判 up-to-date——验证前需 sleep 2
   或强制重建（记录为环境注意事项）。
