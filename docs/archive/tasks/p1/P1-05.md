## 问题与证据

- 无连接数上限：任意连接可入，无拒绝计数；
- Acceptor accept 失败（EMFILE）无处理；
- main.cpp `resetHandler` 在 signal handler 内 exit(0)（EVOLUTION_PLAN §2.1 在案风险：
  非 async-signal-safe；且无 drain/未完成计数）。
- ChatServer main 未忽略 SIGPIPE（P1-04 记录观察）。

## Interface / 可观察行为（EVOLUTION_PLAN §4.5、§9 P1-05）

- `TcpServer::setMaxConnections(N)`：超过 N 的连接被拒绝（accept 后立即关闭），
  `rejectedConnections()` 计数可查询；默认 0 = 不限；
- Acceptor EMFILE：暂停 accept，100ms 后重试（TimerQueue），错误计数可查询；
- `TcpServer::stopAccept()`：停止接收新连接；
- `TcpServer::connectionCount()`：当前活跃连接数；
- SIGINT/SIGTERM（self-pipe 唤醒，handler 只做 write）→ 停止 accept → drain
  （等活跃连接归零，硬截止 5s）→ 强制关闭剩余并打印未完成数 → 退出码 0。
