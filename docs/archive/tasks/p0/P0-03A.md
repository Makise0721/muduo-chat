## 问题与证据

TSan 下 `EventLoopTest.QuitFromOtherThreadStopsLoop` 偶发/稳定超时（30.01s）。
-v 日志证据链：

```
20:07:02 start looping
20:07:02 Channel handle Event revents_: 1      <- 主线程 quit() 的 wakeup 已到达
20:07:34 Channel handle Event revents_: 1      <- 32s 后（析构 queueInLoop quit）才退出
20:07:34 stop looping
```

根因：`EventLoop::loop()`（EventLoop.cc:62）开头 `quit_ = false;` 无条件重置。
时序：主线程 `quit()`（置 quit_=true + wakeup write）发生在 loop() 的 `quit_ = false`
之后、poll 之前 → wakeup 事件被处理但 quit_ 已被重置 → 退出信号丢失。
`EventLoopThread::threadFunc`（EventLoopThread.cc:55）notify 在 `loop.loop()` 之前，
`startLoop()` 返回后外部即可调用 quit() → 窗口真实可达（跨线程 quit 语义承诺被破坏）。

## Interface / 可观察行为

- 跨线程 `quit()` 在 loop 开始 poll 前调用也必须终止 loop（不丢失）；
- 保持 `loop()` 可重入性现状（当前无任何调用方重复 loop()，非目标不引入重复 loop 支持）。

## 非目标

- 不修改 quit()/wakeup() 语义；不引入重复 loop() 重启支持；
- 不修 Logger 竞态（在案 P1-06）。

## 最小实现

当前代码无任何重复调用 loop() 的场景，保留该行只为历史重复 loop 语义）。
