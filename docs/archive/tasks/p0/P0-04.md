## 问题与证据

项目无任何可复现测量能力：无 benchmark 工具、无固定 workload 配置、无结果 schema。
P0 完成闸门要求"benchmark 工具能输出带环境元数据的 JSON 结果"。

## Interface / 可观察行为

`chat-bench <host> <port> <scenario> [--connections N] [--messages M] [--payload-size B] [--duration-ms T]`

- scenario=connect：建立/关闭 N 连接，输出成功/失败数与建连延迟百分位；
- scenario=echo：N 连接 × M 次请求-回显往返，输出延迟 p50/p95/p99/p99.9/max、msg/s、吞吐；
- scenario=slow-consumer：先发送 burst（M × payload_size 字节），再慢速读取，
  输出收发字节数、提前关闭计数；
- 输出单个 JSON 对象（stdout），固定 schema，含 commit/编译 flags/build type/
  CPU model/核心数/kernel/ulimit nofile/payload/连接数/持续时间；
- `tools/chat-bench/bench_stats.h` 提供纯函数 Stats::percentile 与 BenchReport::toJson，
  供单元测试使用（不依赖 OS 调用）。

## 非目标

- 不在同一任务优化网络库或产出正式性能数字；
- 不做 HDR histogram（P0-04 用排序求分位数即可）；
- 不引入第三方依赖（nlohmann json.hpp 已存在于 thirdparty/）。
