## 冻结参数（RED 前定案）

| 参数 | 定案 | 依据 / 备注 |
|------|------|-------------|
| 默认 worker 数 | 维持 1 | 无 benchmark 证据前不变更默认；默认值变更另提一提交 |
| lane 队列上限 | 每 key 有界，生产默认 64（GREEN 冻结，与全局 queue_capacity 默认一致） | 每 Session key 独立有界队列，满则 RejectedFull fail-fast；测试注入小值只经构造参数（`SessionSerialExecutor(loop, workers, globalCap, laneCap)`），绝不作为生产默认 |

| deadline 语义 | 沿用 BlockingExecutor | deadlineMs>0 且自提交起超时：不执行、不回调；任务与队列两侧均跳过 |
| key 映射 | pre-login=ConnectionId；登录后=(UserId,generation) | 登录前同一连接的任务串行；登录后按用户+代次隔离 |
| Conversation 分片 | 不按 Conversation 分片 | Conversation 顺序由 MySQL transaction 决定，不依赖 worker 完成顺序 |
| 公平 | 热 key 不饿死其它 key | ready 队列出队策略需保证公平（如轮转），无界先入者不得独占 worker |
| completion 回传 | 提交时的 origin EventLoop | executor 构造关联的 EventLoop；经 runInLoop 调度（多 Reactor 下仍回主 loop，P2-08 语义不变） |

## Interface / 可观察行为

- **SessionSerialExecutor**（chatserver_core，`chatserver/include/app/` + `chatserver/src/app/` 下新增）：per-key lane + N worker ready 队列（公平出队）。
  - `submit(key, task, completion, deadlineMs) -> SubmitResult{Accepted,RejectedFull,RejectedShutdown}`：同 key 任务严格 FIFO；不同 key 可并行（N worker 并行取 ready 队列）。
  - completion 经 `runInLoop` 调度回提交时的 origin EventLoop（executor 构造关联的 loop）。
  - 全局 ready 队列有界 + 每 key lane 有界：任一满 → RejectedFull fail-fast（含 droppedFull 计数）。
  - deadline 沿用 BlockingExecutor：超时不执行、不回调。
  - shutdown 有界 drain：幂等、拒新（RejectedShutdown）、等在途任务有限完成（任务应为有限执行）。
  - generation 失效沿用 P2-05 beginSessionAttempt 语义：旧 completion 不写新 Session（业务侧判定，executor 不做业务判断）。
- 生产 adapter（SessionSerialExecutor）与 deterministic inline adapter（同步/单步执行，completion 同步回调）共用 submit interface。
- ChatService wiring 替换 BlockingExecutor；config 注入 worker 数（默认 1，`parseExecutorSection` 的 `must be 1` 强制在 correctness 全绿后才删除）。
- 运行期指标语义保持：executor_queue / executor_drop_full / executor_drop_shutdown（SIGUSR1 METRICS 兼容，main.cpp:200-210 不变或最小适配）。

## 非目标

- 无 benchmark 证据前不改变默认 worker 数（默认值变更另提一提交，本卡不变更默认）。
- 不靠全局 FIFO 掩盖业务竞态：同 key 必须 lane 串行、不同 key 并行，不退化为单 worker 全局 FIFO。
- 不碰 P3-12 指标系统（不新增指标体系；仅保持既有 executor 运行期观测）。
- 不按 Conversation 分片；不重写 P3-07/08/09/10 的 DeliveryCoordinator/scheduler/outbox/backfill 语义。
- 不为测试新增只有一个 adapter 的公开 seam；测试穿过生产 interface（SessionSerialExecutor 或其 inline adapter），不读私有容器、不依赖固定 sleep。

## RED 计划

每个场景先写公开 interface 的失败测试（穿过 SessionSerialExecutor/inline adapter 与 config 注入，不读私有容器、不依赖固定 sleep），再实现最小代码。现状下无 SessionSerialExecutor、无 keyed submit、config 强制 workers==1，目标因接口不存在 compile 失败，或（若仅以队列状态断言）因无 lane/多 worker 乱序而无从通过。测试命名具体在 RED 时定，当前清单（8 场景 + 1 对照）：

1. **同 key 1000 任务严格 FIFO**：SessionSerialExecutorTest——单 key 1000 任务，断言执行序 == 提交序（严格 FIFO）；BlockingExecutor 多 worker 下同 key 乱序（P2-06 根因）而失败。
2. **不同 key 慢任务并行**：SessionSerialExecutorTest——key A 慢任务 + key B 快任务在 N(≥2) worker 下 B 不被 A 阻塞、并行完成；单 worker 全局 FIFO 下 B 被 A 阻塞而失败。
3. **热 key 公平**：SessionSerialExecutorTest——热 key 持续灌任务时其它 key 任务仍能推进（不饿死）；无公平出队的实现会饿死而失败。
4. **全局/每 key 满队列 fail-fast**：SessionSerialExecutorTest——全局 ready 满或某 key lane 满 → RejectedFull 且 droppedFull 计数（无界队列或满不拒会失败）。
5. **deadline 超时跳过**：SessionSerialExecutorTest——过期任务不执行、不回调（沿用 BlockingExecutor 语义）；不过期照常。
6. **generation 失效**：SessionSerialExecutorTest/接线测试——(UserId,generation) 切换后旧 key completion 不写新 Session（P2-05 beginSessionAttempt 语义）；旧 completion 污染新 Session 会失败。
7. **completion 回 origin EventLoop**：SessionSerialExecutorTest——N worker 下 completion 执行线程 id == 提交时 EventLoop 线程 id；错 loop 会失败。
8. **shutdown 有界 drain/cancel**：SessionSerialExecutorTest——shutdown 幂等、已接受任务有限 drain、之后 RejectedShutdown；无界等待/拒新语义破坏会失败。
9. **1/2/4/8 worker 行为等价**：SessionSerialExecutorTest——同 key FIFO、不同 key 并行边界、completion 回 loop 在 1/2/4/8 worker 下行为不变（确定性 inline adapter 对照）；行为不等价会失败。

outbox relay 周期 claim/处理与 Delivery 状态机——每消息 MySQL 写工作约 P2-10 的

区间完全重叠（每档内轮间 ±40 msg/s 抖动），且所有负载指向**同一离线目标用户**的
单一 Conversation——MySQL 行锁/事务串行化使多 worker 无法线性扩展（r1/r2 快照
pool_active=1、queue 恒 12-15 即瓶颈在 DB 侧而非 worker 数）；偶发 p99≈2s 尖峰在

worker 数无关。

等价）不代表吞吐曲线支持上调默认值——本报告数字无显著性差异、轮间噪声大于档位差，
按卡「默认 worker 数只由正确性全绿且可复现的曲线决定」不调整默认值。默认值变更
