## Port 重构理由（P4-01 是具体类）

P4-01 把 PresenceDirectory 实现为**具体深模块**（`PresenceDirectory.hpp` 内含 `std::map<UserId,Entry>`、`std::mutex`、Clock 注入、injectFailure seam，无虚函数）。本卡必须让 in-memory 与 Redis 两个 adapter 共用同一领域 interface，因此最小重构：

- `PresenceDirectory`（app/PresenceDirectory.hpp）→ **抽象 port**：保留全部值类型（GatewayId/ConnectionId/SessionEpoch/DeliveryRoute）与结果类型（PresenceError/ClaimResult/RenewResult/ReleaseResult/LocateResult），`claim/renew/locate/release` 变纯虚，加虚析构。
- 原 in-memory 实现迁为 **InMemoryPresenceDirectory**（新文件 InMemoryPresenceDirectory.hpp/.cpp）：语义零改动，`injectFailure` 保留为具体 adapter seam（P4-01 头注释即约定"seam 属具体 adapter，不进入领域 interface"）。
- `chatserver/src/app/PresenceDirectory.cpp` 删除（内容并入 InMemoryPresenceDirectory.cpp）；顶层 CMake 源表对应行替换。
- `tests/unit/PresenceContractTest.cpp` 中 11 处 `PresenceDirectory dir(clock, kTtlMs)` → `InMemoryPresenceDirectory dir(clock, kTtlMs)`（最小重构必改，语义不变）。

## Interface / 可观察行为

- 抽象 port 与 P4-01 完全一致：`claim` 不带 epoch 并生成新 epoch 原子覆盖；`renew/release` compare-and-delete（旧 epoch → NotEpoch 且条目不变）；`locate` 返回路由，TTL 到期 → NotFound 且 expired=true（与从未 claim/release 后可区分）；Redis 故障 → `DependencyUnavailable`。
- **Redis adapter（RedisPresenceDirectory）**：值内嵌 `expiresAtMs`（context-map §3 TTL 落地约束），`locate` 读取后由客户端（注入 Clock）比较判定 expired，**不依赖 key 自动过期删除**；键只含路由与 epoch（gateway/connection/epoch/expiresAtMs），绝不含消息真相。
- epoch 生成：Redis Lua 原子 INCR **全局单调计数器键 `presence:v1:epoch`**（永不被
  release 删除）生成新 epoch——与 in-memory adapter 的"全局单调 epoch 计数器"语义
  一致：release 后重新 claim 的 epoch 仍严格大于旧值（P4-01 契约断言）；跨 restart
  计数器复位后旧 epoch 天然被 fencing（值不匹配）。
- 线程语义：每个 RedisPresenceDirectory 实例持有**单一 RedisConn**（同步请求/响应，非线程共享）；并发 claim 经**每线程/每进程独立实例**（独立连接）触发 Redis 原子性——正是多 Gateway 现实形态。in-memory adapter 保留原单 mutex 线程安全语义。

## 冻结参数（RED 前定案，不改动）

- TTL 默认 30s（30000ms）；测试用短 TTL（1000ms）。
- renew 窗口 = TTL/2：每次续期后应在 TTL/2 内再次 renew（存活余量），常量在卡与测试冻结。
  **L-3（定案）：TTL/2 为调用方（租约调度方）策略，归 P4-05 租约调度；本卡 adapter
  不断言 renew 必须在窗口内发生**——adapter 只保证 renew 成功且按入参 TTL 续期（到期
  判定见 M3 `now >= expiresAtMs`），是否按时续期是调用方的职责，不在本卡接口契约内。
- 键前缀 `presence:v1:`，键 = `presence:v1:<user_id>`。
- 测试用 db=1（隔离，不动 db0）。
- 连接超时 1000ms（命令超时同 1000ms；timeout 故障测试用更短值经构造参数注入）。
- Redis down/超时/断连 → `DependencyUnavailable`（区别于 NotEpoch/NotFound）。
- value 内嵌 `expiresAtMs`（`x`），`locate` 由注入 Clock 判定 `now >= expiresAtMs`（M3 冻结 >= 语义）。

## RED

- 测试：`tests/unit/RedisPresenceContractTest.cpp`（新建），真实 Redis（127.0.0.1:6379 db=1，env `REDIS_TEST_HOST/PORT/DB` 可覆盖），**不 skip**（连接失败即测试失败）：
  1. claim→locate round-trip（路由三要素 + expiresAtMs 内嵌）。
  2. 并发 claim 恰一赢（**真实多线程** 8 线程 × 独立 adapter 实例，barrier 同时 claim 同 user，20 轮：终态=最大 epoch 唯一路由，败者 epoch renew→NotEpoch；**真实多进程** fork 4 子进程各独立连接 claim，终态同理）。
  3. 旧节点延迟 release 不删新租约（claim→claim→旧 epoch release→NotEpoch，新租约原样）。
  4. 旧 epoch renew 被拒且条目不变；renew/release 对过期条目报 NotFound（可区分于 NotEpoch）。
  5. TTL 到期：注入 FakeClock 确定性过期（无 sleep）+ 短 TTL 真实 sleep 对照。
  6. timeout：假慢 Redis（accept 后不回包）→ DependencyUnavailable；连接已关端口 → DependencyUnavailable。
  7. restart（`--save ""`）：claim→重启→条目消失（locate NotFound、expired=false），再 claim 可用——**TTL 语义一致登记**。
  8. Redis down → DependencyUnavailable → 重启恢复可用（claim/locate 正常）。
  9. 键空间隔离：键在 db=1 以 `presence:v1:<id>` 存在、db0 无（前缀+库双层隔离）。
  10. renew 延长到期、release 后重新 claim 新 epoch（契约一致性）。
