## 完成判据

- 同一请求不产生两个 Message（幂等接受：同 key 重试返回原 MessageId/原 sequence，不产生第二行）。
- 已接受 Message 在 retention 内最终 ACK 或保持可查询 Pending/Expired（不静默删除、不无限重试）。
- Conversation sequence 不重复/不倒退（`UNIQUE(conversation_id, sequence)` 实证）。
- 不宣称 exactly-once（at-least-once + 客户端按 MessageId 去重）。

### 与 P2/P3-11 比较与 durable write 成本

- P2-10 ~123 msg/s（101.8/118.5/123.8/122.8）：每消息单条 `INSERT OfflineMessage`，单 worker 串行 DB 写约 8 ms。
- P3-11 w=1 均值 67.5（51.8-99.7）；1/2/4 均值 67.5/68.9/73.4（67-73 区间）。
- 本卡 fresh 均值 65.7、区间 46.8-84.2：与 P3-11 w=1 区间完全重叠、均值持平（65.7 vs 67.5），约为 P2 的 0.53×。
- durable write 成本归因（与 P3-11 一致，MySQLMessageStore.cpp:648/668/709/748）：accept 事务 = UPDATE Conversation.next_sequence + INSERT ChatMessage + INSERT OutboxEvent + INSERT MessageDelivery + COMMIT，每消息 MySQL 写工作约 P2 的 3-4×；外加 outbox relay 周期 claim/扫描（outbox_lag 随轮递增 162→340 = relay batch 100/5s 落后于约 50-85 msg/s 接受速率）、16 条 conversation 同一目标用户行锁、executor 单 worker 串行。METRICS pool_active=1、queue=15（< 容量 64）证明瓶颈在 DB 串行写侧而非队列丢弃。

### 默认 worker 维持 1 结论复核

本卡配置 executor.workers=1（`ExecutorConfig.workers` 默认未动）跑出 46.8-84.2（均值 65.7），落在 P3-11 w=1 区间（51.8-99.7）内；无支持上调默认值的可复现显著性证据（P3-11 已证 1/2/4 区间完全重叠、轮间噪声大于档位差）。结论：维持 1，不改默认，符合卡「默认 worker 数只由正确性全绿且可复现的曲线决定」。
