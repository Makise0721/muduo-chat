## 接口/行为

- `UserRepository` port 扩展：`authenticate(id, password) -> AuthResult{ok,id,name,state}`
  与 `updateState(id, UserState)`；UserState{Offline, Online}；InMemory/MySQL 双
  adapter 实现（MySQL 全 prepared statement），契约测试双跑。
- `ChatApplication`：session generation——`beginSessionAttempt(userId)`（登录尝试/
  登出/断开时递增）、`isSessionCurrent(userId, gen)`（异步 completion 校验）；
  `authenticate`/`updateUserState` 线程安全透传（worker 线程调用）。
- 登录用例迁移：认证 + 好友列表 + 离线消息查询全部在 BlockingExecutor worker
  执行（EventLoop 内零同步 SQL）；**单会话以 _userConnMap（活动连接）为真相**：
  重复登录（map 有）→ errno=2；断开残留的 DB online（map 无）→ 放行登录并异步
  补 UPDATE online；stale completion（代次不符）丢弃，不写状态不响应。
- 登出/断开迁移：map 更新同步（内存）、UPDATE offline 异步提交；代次递增使在途
  登录 completion 失效。
- `ChatService::bindLoop(loop)`（main 启动前）+ `shutdownApp()`（loop 退出后）：
  阻塞执行器生命周期与 EventLoop 对齐。

## 过程（RED → GREEN）

- RED-1（H1 回归）：断开重连登录收到 errno=2——2 worker 并行使断开 UPDATE
  offline 与重连 authenticate 竞争；DB state 无法区分"真重复登录"与"断开残留"。
  → 单会话判定改以 _userConnMap 为真相（completion 在 loop 线程检查），DB 影子
  异步落库；DomainCharacterization 10+5 轮稳定。
- RED-2（TSan）：SessionApplicationTest 析构时 loop 线程仍执行 completion 读
  ChatApplication → data race → 测试末尾加 drainLoopCompletions 屏障（queueInLoop
  哨兵等待先前 completion 全部执行完再析构）。
- GREEN：SessionApplication 7/7（登录/错密码/重复登录/登出/断开/stale 丢弃/
  快速断开重连），契约 12/12。
