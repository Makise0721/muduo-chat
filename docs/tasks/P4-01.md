## Interface / 可观察行为

- `PresenceDirectory::{claim, renew, locate, release}` 全部携带 epoch（SessionEpoch）；claim/renew 携带 `(user_id, gateway_id, connection_id, epoch)`，release 携带 `(user_id, gateway_id, connection_id, epoch)`。
- `claim` 总是生成新 epoch 并原子覆盖既有条目，无需旧 lease 已过期（P4-00 关键不变式，cluster-context-map §3），返回新 epoch 与写入结果。
- `renew`/`release` 为 compare-and-delete：携带的 epoch 必须与当前条目一致才生效，epoch 不匹配返回可区分错误且条目不变。
- `locate` 返回当前路由 `(gateway_id, connection_id, session_epoch)`；TTL 到期视为不存在（与从未 claim 的结果可区分）。
- TTL 到期判定冻结为 `now >= expiresAtMs`：`now == expiresAtMs` 恰在到期时刻即视为不存在（expired=true），不因实现/容器差异放宽为 `>`（M3 冻结）。
- TTL 落地约束（P4-02 可实现性）：TTL 必须 value 内嵌（`expiresAtMs`），`locate` 读取后由客户端比较判定 expired，不依赖 key 自动过期删除。
- `injectFailure` 是本卡 in-memory adapter 的具体 seam（per-op 故障注入，模拟依赖不可用）；P4-02 起 `DependencyUnavailable` 来自真实 Redis 错误，seam 属具体 adapter，不进入领域 interface。
- dependency unavailable（adapter 注入失败，模拟依赖不可用）与各业务错误可区分。
- 状态转换原子：单次调用二值结果（成功/失败），无部分状态。

## 完成定义

- 状态转换原子：单次调用二值结果，无部分状态。
- 错误可区分：旧 epoch renew/release、TTL 到期、并发 claim 冲突、clock jump、dependency unavailable 各有唯一可断言结果。
- 无 epoch 回退：renew/release/locate 不会观察到低于当前 claim 的 epoch；release 后条目消失，后续 claim 生成新 epoch。
