## 接口/行为

- `MessageRepository` port：`storeOffline(userId, payload) -> StoreResult`、
  `takeOffline(userId) -> vector<OfflineMessage>`（按 id 顺序取走并清空）；
  payload 为协议原文（原样补投）；重复请求（同 payload 两次）产生两条记录
  （去重属 P3 可靠消息语义，现状不处理）；读失败不删队列（至少一次语义）。
- `GroupRepository::members(groupId)`：成员 id 列表；**不存在的群 = 空列表**
  （与现状 SELECT 行为一致，群聊不区分）。
- ChatApplication 第 4 port 注入 + 透传（storeOfflineMessage/takeOfflineMessages/
  groupMembers）。
- 单聊迁移：目标在线 → 原样转发 + ACK（内存操作无 SQL）；离线 → 异步
  storeOffline（errno=0 = 已接受非已投递，P3 语义另行区分）。
- 群聊迁移：异步查成员 → completion 在线转发（锁内拷贝连接）/离线逐条异步
  入队（单 worker FIFO 保序）/发送者 ACK errno=0（B-19 无条件 0 保持）。
- 登录补投：loadLoginExtras 离线部分改用 takeOfflineMessages（原 SQL 删除）；
  好友列表查询为 P2-06 后遗留原生 SQL（登录用例附属，另行收敛）。
