## Interface / 可观察行为

- **OfflineBackfill runner**（chatserver_core，`chatserver/src/db/` + `chatserver/include/`）：可重入、checkpoint、dry-run、批次有界。
  - 源行读取：`OfflineMessage` 按 id 有序、批次有界（LIMIT/checkpoint 高水位）。
  - 每行解析：可解析旧行 → ledger Conversation（必要时）+ ChatMessage + MessageDelivery（recipient=userid），幂等键 `client_message_id = legacy:<offline_id>`；已存在同键 → 跳过（重复运行不增加 Message）。
  - 不可解析行（坏 JSON/乱码/超界>500/非 UTF-8）→ quarantine（可查询，含源 id/用户/原因/原始 payload），绝不静默删除。
  - dry-run：只统计+hash，不写任何 ledger/quarantine 行。
  - 计数/hash 守恒：源行 = migrated + quarantine；重复运行后 ledger Message 数不增。
- **quarantine 可查询**：SQL 谓词可定位 quarantine 行，便于人工处理。
- **cutover 开关**：config 注入控制登录/补投默认路径——过渡期"读新 ledger + 仅未迁移旧行 fallback"，cutover 后不再调用 storeOffline/takeOffline。
- **ReliableMessaging/MessageStore 最小兼容读接线**：backfill 复用既有 ledger 写接口（getOrCreateConversation/insertMessage/insertDelivery 等）；不为 backfill 新建仅测试可见的公开 seam。

5. **源计数守恒**：BackfillReentrancyTest——源行 = migrated + quarantine（含不可解析行）；dry-run 与实跑计数一致。
6. **重复运行不增加 Message**：BackfillReentrancyTest——两次 run 后 ChatMessage 行数相同（`legacy:<offline_id>` 幂等）。
