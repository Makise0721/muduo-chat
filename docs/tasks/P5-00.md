## 设计决定（开卡定案，RED 前冻结）

- **D1 文件布局 = 双 header-only 头**：`app/Telemetry.hpp`（interface + 白名单校验 + Snapshot 类型）与 `app/RecordingTelemetry.hpp`（纯内存测试 adapter，含 Clock 注入）。零 .cpp → chatserver_core 源表零修改（先例：ReliableMessageMetrics.hpp 全 header-only）。生产 adapter 属阶段 B，不在本卡出现。
- **D2 API 形状**（OTel 语义形状的最小子集）：`addCounter(name, delta, labels)`（单调，接口层无递减操作）、`setGauge(name, value, labels)`（last-writer）、`recordHistogramSample(name, valueMs, labels)`、`beginSpan(name, parentSpanId=0, labels)`（返回 recorder 内唯一 spanId，0 保留 = root）、`endSpan(spanId, errored)`。span 属性（trace attrs）本阶段不做——阶段 A 只要求 parent/error 完整可观察。beginSpan 创建/命中 (name,labels) 系列并计入 spansStarted/spansErrored/时长分位数。
- **D3 label 白名单冻结**（§9.8 冻结值清单项；初始集合 = P3-12 已冻结的四低基数维度，新增 key/value 走 §9.8 白名单变更流程）：
  - `delivery_state` ∈ {pending, inflight, acknowledged, expired}（对齐 ReliableMessageMetrics::DeliveryState）
  - `accept_outcome` ∈ {accepted, duplicate, conflict, too_many_recipients}（对齐 AcceptOutcome）
  - `error_class` ∈ {timeout, unavailable, rejected}（初始有界集）
  - `legacy` ∈ {true, false}
  - UserId/MessageId/ClientMessageId/ConnectionId 及其余任意 key 一律拒绝。
- **D4 拒绝语义**：label 违规（key 不在白名单或 value 越界）→ **先 ++rejectedLabels 再抛 invalid_argument**（拒绝计数可见 + 编程错误显式暴露；阶段 B 生产入口经 recordBestEffort 同款守护吞掉异常，计数保留）。系列基数预算（kMaxSeries=64 个不同 (name,labels) 系列）超限 → ++rejectedSeries 并抛。endSpan 未知/重复 spanId → 抛 invalid_argument（沿 ReliableMessageMetrics recordDeliveryTransition unknown identity 先例，不计数）。
- **D5 线程安全策略 = 内部 std::mutex（否决 atomics）**：理由 (a) Snapshot 必须是多字段一致视图，per-field atomics 会撕裂快照；(b) nearest-rank 分位数需排序样本容器，原子化不可行；(c) 与 ReliableMessageMetrics 线程契约同款（其头注释已论证记录面多线程 + 快照面 EventLoop 线程需内部锁）。TSan 设计目标：全部状态访问持同一 mutex_。
- **D6 有界内存**：已完成 span 记录日志上限 kMaxRecordedSpans=4096，超限丢最旧（P3-12 H2 有界内存纪律同款）；histogram 样本按系列保存于 RecordingTelemetry 内部（测试 adapter，规模由测试控制），Snapshot 只输出标量分位数。histogram 与 span 时长样本为测试规模受控类别（阶段 A 测试 adapter 不设样本上限）；阶段 B 生产 adapter 必须实现有界样本预算（登记 P5-00 阶段 B 前置项）。
- **D7 快照惯例**：`SeriesSnapshot` 全标量 POD ×固定数组 `series[kMaxSeries]` + `seriesCount` + `rejectedLabels`/`rejectedSeries` → 整体 standard_layout（static_assert 断言），跨 recorder 逐字段求和聚合（gauge 为 combined-stream last-writer，histogram 分位数按合并样本重算）——沿 ReliableMessageMetrics::Snapshot 惯例。
