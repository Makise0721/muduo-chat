## 问题与证据

审查报告 F-04：`StreamCodec::encode`（void）不拒绝超过 16 MiB 的 body，不校验 header 的
body length 与实际 body 一致，无失败通道；A-02：ChatServer 协议错误只 `shutdown()`
（half-close 写端，恶意客户端可继续占用连接）。

## Interface / 可观察行为

- `EncodeResult { Ok, TooLarge, InvalidFrame }`；encode 失败时 output 不被修改；
- `StreamCodec::encode(Frame, Buffer*) -> EncodeResult`：自校验 magic/version/headerLength/
  flags/reserved/contentType/bodyLength==body.size()；body 超 maxBodyLength_ 为 TooLarge；
- decode 增加 contentType==kContentTypeJson 校验（否则 ProtocolError）；
- `OutputCodec` 小接口：`encodedSize(payloadBytes)` + `encode(message, Buffer*) -> EncodeResult`；
  BinaryFrameCodec/LegacyJsonLineCodec 实现之；不新增第三抽象层；
- TcpConnection 输出编码器签名返回 EncodeResult（编码失败 → SendResult::TooLarge）；
- ChatServer 协议错误路径改 `forceClose()`（连接最终释放，非 half-close）；
- v2 帧线格式（golden bytes）不变；v1/v2 业务结果等价。

## 非目标

- 不做发送准入预算（P1R-03）；不改 decode 之外的解析语义；
- 不为 messageType 建白名单（业务层语义）。

   decode 加 contentType 校验；

   BinaryFrameCodec（存 maxBodyLength_，encode 超限 TooLarge）+ LegacyJsonLineCodec 实现；
3. TcpConnection.h：OutputEncoder 签名返回 EncodeResult；sendInLoop 编码结果非 Ok → TooLarge；

5. 测试：StreamCodecTest/BinaryFrameCodecTest/LegacyJsonLineCodecTest 补 encode 结果断言 +
   边界/非法帧/失败不改 output/encodedSize；TcpConnectionTest:171 签名同步。

## 完成定义

- 任何可编码消息有可预知准确帧大小（encodedSize）；编码失败不修改 output；
- encode/decode 上限一致（16 MiB 硬上限、bodyLength 自校验）；非 JSON contentType 双向拒绝；
- 协议错误连接最终释放（进程级证据）；golden bytes 不变；v1/v2 等价 smoke 通过。
