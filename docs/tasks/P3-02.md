## 问题与证据

- P3 不把 `MessageRepository` 扩成 SQL 风格 CRUD，而是建立一个深 `ReliableMessaging` 模块：网络层只学习 accept/acknowledge/sessionAvailable/sessionClosed 四类动作，重试、租约、Conversation 分配、幂等全部隐藏在模块内部（计划 §3）。
- 领域状态机逻辑必须放 ReliableMessaging 本体，adapter 只管存储；同一 contract 将复用于 MySQL adapter（P3-04），因此测试只穿过 ReliableMessaging interface，不读取容器（计划 §5 P3-02 完成定义）。
- 幂等键 `(sender, ClientMessageId)`、Delivery 状态机、10 故障点的语义由 [message-reliability.md](../specs/message-reliability.md)（P3-00 定稿）固定：同键重试返回原 identity；不同 payload 复用键 → IdempotencyConflict（不是 duplicate）；同 `(recipient, conversation)` 单在途；lease 到期可重领；Conversation 内 sequence 严格递增。

## Interface / 可观察行为

- 领域值类型：`MessageId`、`ClientMessageId`（可打印 ASCII 1..64，非法抛 `std::invalid_argument`，另提供 `isValid`）、`ConversationId`、`ConversationSequence`、`UserId`、`GroupId`、`SessionIdentity{userId, generation}`（AuthenticatedSession 的 P3-05 占位）、`Message`、`SendMessageCommand`（direct/group；群消息接受时快照接收者 → 命令携带成员列表）、`AcceptOutcome`（Accepted{messageId,conversationId,sequence,duplicate} / IdempotencyConflict / 错误）、`AckOutcome`（Acknowledged/Idempotent/NotRecipient/NotFound）、`Delivery`（recipient/state/lease/attempt）、`DeliveryAttempt`。raw JSON 不进领域类型（协议解析是 P3-06）。
- 外部 interface：`ReliableMessaging(store, sink, clock, leaseMs)` 提供 `accept(session, cmd)`、`acknowledge(session, messageId)`、`sessionAvailable(session)`、`sessionClosed(session)`、`start()`、`stop(deadlineMs)`；内部 seam `MessageStore`（InMemory adapter）、`DeliverySink`（Recording adapter）、`Clock`（可控）。
- 线程调用约束：`ReliableMessaging` 实例须由单一调用者串行驱动（P3-05 接入后为 `SessionSerialExecutor` 或等价串行执行器）；接口内部非原子（读-改-写），并发调用未定义行为。
- 语义：同 `(sender, ClientMessageId)` 幂等返回原结果；不同 payload 复用 key → IdempotencyConflict；Conversation 内 sequence 严格递增；Delivery Pending→InFlight→Acknowledged（Expired 枚举在案，转移 P3-08）；lease 到期可重领；同 `(recipient, conversation)` 至多一个未确认 sequence 在途（head-of-line，ACK 后放行下一 sequence）；断开 → 名下 InFlight 立即回 Pending；ACK 主体只来自 Session，他人 ACK 不越权。
- 不实现 SessionRegistry：本体只按 sessionAvailable/sessionClosed 的显式通知行动，不主动知道谁在线（P3-05 深化）。

## 遗留/衔接

- **P3-07（DeliverySink 真实 adapter）**：spec §3 要求仅 `TcpConnection::SendOutcome.disposition` 已接受才记录 attempt、Closed 保留 Pending；现状 `DeliverySink::deliver` 返回 void 且 claim 先置 InFlight，与本任务 interface 无冲突但未对齐 spec。**本任务不改接口**：P3-07 需要 deliver 返回结果通道（或等价准入回调），届时改 port 签名。
- **P3-04（群成员快照语义）**：本任务接受现状——接受时快照的群成员原样成为接收者（含 sender 本身、空成员群不拒绝）；P3-04 决定"发送者是否自投递、空成员群是否拒绝"。
- **C++11 聚合初始化**：`SessionIdentity`/`SendMessageCommand`/`Delivery` 已加显式构造函数，`SessionIdentity{...}` 式写法在 C++11 可编译（测试原用 C++14 逃过）。验证命令：`g++ -std=c++11 -I<include> -c chatserver/src/app/ReliableMessaging.cpp`、`g++ -std=c++11 -I<include> -c chatserver/src/app/InMemoryMessageStore.cpp`（chat-server 生产目标本即 `cxx_std_11`）。
