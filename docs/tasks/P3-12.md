## RED 指标清单（卡内冻结，不随实现调整）

- 计数（counter）：accepts、duplicates、conflicts、rejected-too-many-recipients。
- 状态（gauge/状态计数）：pending、inflight、acked、expired（Delivery 状态机 spec §3）。
- 投递（counter）：attempts、retries（attempt_count>1 计 retry）。
- 延迟（histogram 或 p50/p95/p99）：ACK latency（MESSAGE_ACCEPTED 到 DELIVERY_ACK 的时延）。
- 陈旧度（gauge）：oldest pending age。
- outbox（gauge/counter）：lag（未 processed OutboxEvent 数量/存在性）、poison（处理失败事件计数）。
- legacy（counter）：legacy-mode count（spec §5.1：缺 client_message_id 走 implicit-ack 的在线/离线 Delivery 单独计数）。
- **label 基数约束（测试必须拒绝）**：UserId、MessageId、ClientMessageId 等高基数字段禁止作为 metric label；只允许固定低基数的枚举/结果维度（如状态、错误类别、legacy 与否）。

## Interface / 可观察行为

- SIGUSR1 METRICS 快照扩展：在既有 `METRICS pool_* executor_*` 行上追加可靠消息字段（保持整行单次输出与 key=value 格式兼容）。
- 结构化事件：ReliableMessaging/DeliveryCoordinator/outbox 在状态迁移与接受/重试/过期/legacy 判定处发出结构化事件（或等价计数更新），test recorder 可逐事件断言 counter/gauge/histogram 变化。
- 指标语义与 spec §3 状态机一致：状态计数守恒（pending+inflight+acked+expired=已接受 Delivery 总数，legacy implicit-ack 计入 legacy-mode count）；attempts≥acknowledged 对应行数，重试只增 attempts。
- 不引入高基数字段 label；不改变现有 pool/executor 指标语义。

## 非目标

- 不改 P3-13 性能矩阵范围外内容（本卡只建指标与故障证据，不优化吞吐）。
- 不做 Prometheus/OTel 等生产导出（P5-00 的 telemetry interface 与基数预算）；本卡只扩展进程内 METRICS 快照与测试 recorder。
- 不重写 Delivery 状态机/outbox/scheduler 语义（P3-07/08/09/10 保持）；指标只是可观测性。
- 不为测试新增只有一个 adapter 的公开 seam；测试穿过生产 interface 或受控 clock/event 注入，不读私有容器、不依赖固定 sleep。

## RED 计划

每个场景先写失败测试（ReliableMessageMetricsTest 穿生产 interface 的 recorder；fault harness 穿真实进程 + 端口/DB），再实现最小代码。现状下可靠消息指标不存在：断言计数器/状态 gauge/histogram 存在的测试因接口/数据缺失失败。命名在 RED 时定，当前清单：

1. **accepts/duplicates/conflicts/too-many-recipients**：同 key 首提 accepts+1、duplicate=true 只 duplicates+1；冲突 payload 复用 key conflicts+1；超 fan-out cap 拒绝且计数；test recorder 对每个接受结果断言。
2. **pending/inflight/acked/expired 状态计数**：claim→inflight、ACK→acked、超时→pending、过期→expired，逐状态迁移断言 gauge 转移且守恒。
3. **attempts/retries**：首次投递 attempts+1；ACK 丢失重投同 MessageId attempts+1 且 retries+1。
4. **ACK latency**：histogram/p50/p95/p99 由 recorder 采样；重复 ACK 不计新样本。
5. **oldest pending age**：可注入 clock 下断言陈旧度单调且过期后归零/消失。
6. **outbox lag/poison**：accept 后未处理事件→lag>0；relay 处理→lag 下降；poison 事件（不可处理）poison+1。
7. **legacy-mode count**：缺 client_message_id 的 direct/group 消息走 implicit-ack，legacy-mode count+1（spec §5.1）；v2 消息不增加。
8. **高基数 label 拒绝**：把 UserId/MessageId/ClientMessageId 作为 label 提交的测试必须失败（assert label 白名单/基数预算）。

## 最小实现

- 扩展现有 METRICS 快照（main.cpp:200-210）与结构化事件：在 ReliableMessaging/DeliveryCoordinator/outbox 路径挂最小计数/采样点，输出追加可靠消息字段；不动状态机语义。
- **新有界公开查询登记（GREEN 阶段一，metrics 最小扩展，MessageStore 默认空实现沿用既有模式）**：
  - `expireDeliveriesDetailed(nowMs, limit, out)`：与 `expireDeliveries` 等价地把到期 Pending/InFlight → Expired，并逐行报告 (messageId, recipient, fromState) 供 Recorder 记录 Expired 状态转移（默认实现回退 `expireDeliveries`，既有测试替身不受影响；InMemory/MySQL override）。
  - `countUnprocessedOutboxEvents()`：outbox lag gauge 用（未 processed 事件总数；默认 0，InMemory/MySQL override）。
  - 说明：oldest pending age 采用事件驱动推导（Recorder 的 head 语义），不另加 DB 聚合查询；进程重启后 Recorder 从空重建，跨重启严格守恒只由单元测试保证。
- ReliableMessageMetricsTest（tests/unit/）：test recorder 断言冻结指标清单的 counter/gauge/histogram 与状态计数守恒；拒绝高基数 label。
- ReliableMessageFaultProcess（tests/scripts/ 新增，参照 OutboxCrashRecoveryProcess/LegacyCutoverRehearsalProcess 模式注册于 tests/CMakeLists.txt，RESOURCE_LOCK chat_server_ports）：进程代理只 drop/delay/kill 与收日志/查 DB 状态/对齐客户端可见结果，不窥探 DB 私有实现；每 kill 点保留原始日志、DB 状态、客户端可见结果与恢复动作。

（幂等吞掉）、pending 巨大，绝对与相对计数断言都失真——这正是 H1 想断言
"无下溢/守恒"的对象被同 identity 陈旧状态污染。

### GREEN（测试侧最小修复，`DeliveryRetryTest.cpp:358-410`）

- 每轮（含 gtest_repeat 迭代）用唯一 recipient：`static uint64_t s_run` +
