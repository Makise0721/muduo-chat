## 最小实现

- `chatserver/include/app/MySQLMessageStore.hpp` + `chatserver/src/app/MySQLMessageStore.cpp`：实现 MessageStore port；内部 `TransactionGuard`（RAII acquire(5000ms 带 deadline)/SET TRANSACTION ISOLATION LEVEL READ COMMITTED/START TRANSACTION/COMMIT/ROLLBACK，析构未提交回滚兜底）；thread_local accept 事务上下文（ReliableMessaging 单调用者约束 → 并发测试每线程一个 rm，连接租约按线程隔离）；故障注入 FaultHook（adapter 构造参数，非 MessageStore 公开接口，不进 ReliableMessaging 公共接口）。
- accept 事务顺序：cap 检查（事务外，无行）→ BEGIN → Conversation 查找（direct low/high 归一化 / group group_id）→ 不存在则 INSERT Conversation + 链接行（1062 → ROLLBACK + 新事务重读已提交对话）→ `SELECT next_sequence FROM Conversation WHERE id=? FOR UPDATE`（同对话串行点）→ UPDATE next_sequence → INSERT ChatMessage → INSERT OutboxEvent（payload=命令快照 JSON）→ 逐接收者 INSERT MessageDelivery（1062 = 同 (message, recipient) 已存在 → 幂等 no-op）→ 达快照预期接收者数时 COMMIT（提交先于 accept 返回）。
- 1062（sender, client_message_id）竞争：INSERT ChatMessage 1062 → ROLLBACK + 新事务读已提交原 Message（RC 隔离保证读到）→ samePayload → 返回原结果（不消费 sequence）；不同 payload → IdempotencyConflict。
- 成员快照保序：MessageDelivery 无序号列（0002 已冻结、0003 迁移会破坏 P3-03 已注册测试的版本/列断言）→ 命令快照（kind/direct_recipient|group_id/members 有序数组）写入 OutboxEvent.payload JSON；content 走 ChatMessage.content 列原样 round-trip（不编码，保 16MB 列上限）；findAccepted/findMessage JOIN OutboxEvent 重建命令。
- 时间编码：ms → DATETIME(0) 秒（截断，任务卡登记：契约测试时间值均为秒的倍数 round-trip 精确；P3-08 需要亚秒精度时另提 migration）；lease_owner "uid:gen"；state TINYINT 0..3（adapter 内隐藏）。
- 错误映射：1205/1213/2006/2013/1053/2003/池错误 → DependencyBusy；1452 → NotFound；1406/1366/1300/1062（未期望处）→ Storage。
- 不写 SQL 到业务查询路径的用户输入（全部 prepared statement）。

- 设计决策（本任务冻结）：
  - 事务边界：MessageStore port 无事务边界 → adapter 用 thread_local accept 上下文（连接租约按线程隔离，ReliableMessaging 单调用者约束下的并发测试每线程一个 rm）；`insertDelivery` 计数达 getOrCreateConversation 由命令快照确定的预期接收者数时 COMMIT（提交先于 accept 返回，Durable acceptance）；0 成员快照（空群）无 Delivery 可插 → insertMessage 尾部内联 COMMIT（accept 返回前提交）；边界方法（findAccepted/deliveriesBy*/findMessage/updateDelivery）先提交遗留事务（防御）；异常路径 rollbackAndClear，线程退出 guard 析构 ROLLBACK 兜底。COMMIT 失败（如 1205）时 commit() 显式回滚（尽力而为，ROLLBACK 再失败记录日志、析构兜底再试），保证归还池的连接无未提交事务——自愈不再依赖 START TRANSACTION 隐式提交。
  - 事务顺序：cap 检查（事务外，无行）→ BEGIN（READ COMMITTED，见下）→ Conversation 查找（direct low/high 归一化；group 按 group_id）→ 不存在则 INSERT Conversation+链接行（1062 → 回滚+新事务重读已提交对话）→ `SELECT next_sequence ... FOR UPDATE`（同对话串行点）→ UPDATE → INSERT ChatMessage → INSERT OutboxEvent（payload=命令快照 JSON）→ 逐接收者 INSERT MessageDelivery → 达计数 COMMIT。
  - 幂等竞争：ChatMessage 1062 → 回滚（不消费 sequence，无空隙）+ 新事务内读已提交原行（RC 隔离保证读快照新鲜）→ samePayload 相同返回原结果、不同抛 IdempotencyConflict；串行重复路径仍由 findAccepted + ReliableMessaging 正常返回（duplicate=true）。
  - 错误映射：1205/1213/断连/池超时 → DependencyBusy（调用方同 key 重试，并发测试内以 16 次上限重试）；1452 → NotFound；1406/1366/1300/1062（未期望处）→ Storage；cap 超限 → TooManyRecipients（同 key 重试稳定同错误）。
  - 成员快照保序：MessageDelivery 无序号列且 0002 已冻结（0003 迁移会破坏 P3-03 已注册测试的版本/列断言，否决）→ 命令快照（kind/direct_recipient|group_id/members 有序数组）随 OutboxEvent.payload（nlohmann JSON，仓库既有依赖）；content/client_message_id 走列原样 round-trip（不编码，保 16MB MEDIUMBLOB 上限）；findAccepted/findMessage JOIN OutboxEvent 重建命令。payload 格式由本任务冻结，P3-09 relay 消费。
  - 时间/编码：ms → DATETIME(0) 秒（截断；契约/随机契约的时间值均为秒的倍数，round-trip 精确；P3-08 亚秒需求另提 migration）；lease_owner "uid:gen"（NULL=无租约）；state TINYINT 0..3（adapter 内隐藏）。
