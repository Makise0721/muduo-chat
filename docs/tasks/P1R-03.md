## 问题与证据

审查报告 F-01：`SendResult` 无法让生产者可靠停止——
1. loop 线程内一次发送跨过 pause 水位后仍返回 Accepted（无"本条已接收但应暂停"表达）；
2. 非 loop 线程只检查单消息大小，随后把消息排入 pendingFunctors_ 并立即返回 Accepted——
   未编码、未进 output buffer 的数据不受 hard limit 约束（跨线程 pending 无界）；
3. hard limit 只在 append 前检查 buffer，无"当前+本次帧"原子准入（单帧可越界）。

## Interface / 可观察行为

```cpp
struct SendOutcome {
    enum class Disposition { Accepted, WouldBlock, Closed, TooLarge };
    enum class Pressure { Normal, PauseProducer };
    Disposition disposition;  // 本条是否已接收
    Pressure pressure;        // 生产者是否应暂停
};
SendOutcome send(std::string message);
void setPressureCallback(const PressureCallback &cb);   // 低水位恢复通知
void setOutputCodec(const OutputCodec *codec);          // 取代 setOutputEncoder 回调
```

- 预算：连接级原子 outstandingBytes（编码后帧大小累计：pending send + outputBuffer 未写出）；
  send 在**任意线程**先 CAS reserve（outstanding+frameSize <= hardLimitBytes 才接受），
  入队前完成准入；写出（nwrote/handleWrite）或丢弃（forceClose）时释放；
- 语义：Accepted+Normal=已接收可继续；Accepted+PauseProducer=本条已接收但应暂停
  （reserve 后越过 pauseReadBytes）；WouldBlock+PauseProducer=本条未接收（预算满，等
  恢复通知后重试）；Closed/TooLarge 语义保留；
- 恢复通知：outstanding 从 >resumeReadBytes 降到 <=resumeReadBytes 的下降沿触发一次
  （再越过再触发）；仅 loop 线程调用回调；
- 空消息也有帧开销（v2 header 20B / v1 换行 1B），不能绕过字节预算；
- setOutputEncoder 删除（两个调用点迁移至 OutputCodec*）。

## 最小实现

1. TcpConnection.h：SendOutcome；setPressureCallback；setOutputCodec（const OutputCodec*，
   nullptr=裸发）；成员 outstandingBytes_（atomic）、lowWaterArmed_（loop 线程）、
   pressureCallback_、codec_；删 SendResult/setOutputEncoder；
2. TcpConnection.cc：
   - send()：state 检查 → codec_->encodedSize() 帧大小 → TooLarge 检查 →
     tryReserve CAS → overPause 判定 → loop 线程直送/runInLoop(sendInLoop)；
   - sendInLoop(message, frameSize)：编码（失败释放预算→TooLarge）→ 写 socket（nwrote
     立即 release）→ append buffer（remaining 保留预算）→ checkPause；
   - handleWrite：写出字节 release + 低水位下降沿回调（低水位只触发一次）；
   - forceClose/connectDestroyed：outstanding 清零 + 取消 armed；
   - sendInLoop 不再返回 Backpressured（预算拒绝发生在入口 WouldBlock）；
3. ChatServer：setOutputCodec(&_frameCodec)（v2）；v1 不设；
4. 测试：BackpressureTest 重写为 SendOutcome 语义（预算满 WouldBlock、跨 pause
   AcceptedPaused、恢复回调一次、关闭后 Closed、空消息不绕过预算、跨线程持续发送
   outstanding 不越 hard）；TcpConnectionTest/TcpServerTest 适配。

## 调试记录

1. EmptyMessages 测试初版 limits 非法（resume 32K > hard 1K）被 setWriteBufferLimits 静默
   拒绝→默认 64MiB→永不 WouldBlock——修正为 resume=256 < pause=512 < hard=1024。
2. **stall timer 循环引用泄漏（LSan）**：`stallTimerId_`（shared_ptr<Timer>）与 timer 捕获的
   self 成环——未触发/未取消的 stall timer 使 TcpConnection 永不析构（75/76/79 三个测试
   触发，stallTimeout=2000ms > 测试时长）。修复：startStallTimer 改捕获 weak_ptr + lock 提升
   （forceClose 语义不变；连接已亡则跳过）。
3. ResumeCallback 测试语义：直发成功也会产生下降沿回调（128K→0）——"WouldBlock 后只回调
   一次"改为快照 before + snapshotDone 标志，断言 before+1（两个独立下降沿均合法）。
4. 跨线程 WouldBlock 时 startStallTimer 经 runInLoop 调度（loop 线程执行，stallActive_ 防重）。
5. C++11 适配：SendOutcome 需显式构造函数（默认成员初始化器使聚合失效）；
   bind 重载需 static_cast；OutputCodec::encode 改 const（TcpConnection 持 const 指针）。

## 完成定义

- 任何线程 send 都不能让已接收未写出字节超过 hard budget（CAS 原子准入）；
- 消费者能依据公开结果无重复、无丢失地停产与恢复（WouldBlock+Pause /
  恢复回调一次）；
- 跨 pause 本条消息结果无歧义（Accepted+PauseProducer）；
- 关闭时预算归零；空消息不能无限排队。
